## [Unreleased]

### Added
- M0 scaffold: Vite + React + TypeScript (strict) + Tailwind, ESLint (flat config, `src/core` import boundary), Prettier, Vitest.
- Repo meta files: README, LICENSE (MIT), SECURITY.md, CONTRIBUTING.md, issue/PR templates, CODEOWNERS, Dependabot config.
- CSP `<meta>` per SPEC §9; ADR-0001 (client-only) and ADR-0005 (Pages + meta CSP).
- CI workflow definitions (`ci`, `codeql`, `deploy`, `scorecard`) — written but not yet run (no remote repo in the local-only phase).
- Synthetic CPCV draft template (`templates/cpcv/`) plus its authoring tooling (`scripts/build_template_docx.py`, `lint.py`, `render_demo.py`).
- M1 tag engine (`src/core/tags`, `src/core/docx`): tag parser for SPEC §3 grammar (value tags, blocks, `{{#se}}` conditionals, `cl`/`pt`/`al`/`ref`, `\{{` escape) with all applicable error codes; bounded `.docx` zip reading (ADR-0007, `fflate`); paragraph run-map extraction incl. table cells; span replacement preserving the first run's formatting with automatic XML escaping (ADR-0002). `REF_TARGET_HIDDEN` and `META_UNKNOWN_FIELD` are deferred to M3 (need numbering/meta-schema machinery not built yet).
- Synthetic split-run/table-cell fixture generator (`scripts/generate-fixtures.ts` → `fixtures/split-runs.docx`).
- M2 validators/formats (`src/core/validators`, `src/core/formats`): NIF/NIPC checksum, IBAN PT mod-97, dd/mm/aaaa date parsing with real-calendar validation, pt-PT eur (integer cents) and int parsing/formatting, CC format check (marked experimental — no verified checksum spec was available, see `src/core/validators/cc.ts`). pt-PT number-to-words extenso (euros + cêntimos) and clause ordinals (1-20 per SPEC §4, algorithmic beyond that). All SPEC §6 test vectors covered, plus property tests (IBAN mod-97 invariant, extenso never crashes/negatives up to ~10M).
- M3 template package, numbering, rules (`src/core/template`, `src/core/numbering`): `template.meta.json` loader with `META_UNKNOWN_FIELD` cross-checking against tag ids actually used in the body; cl/pt/al numbering + `{{ref:id}}` display text resolution where hidden blocks don't consume numbers; static block-nesting-path analysis powering `REF_TARGET_HIDDEN` (a ref whose target anchor could be hidden while the ref itself renders); cross-field rule evaluation (`sum_eq`/`date_after`/`date_before`/`differs`/`required_if`); a 4-layer validation engine (format/checksum, conditional required, cross-field rules, structural) assembling all of the above. `npm run lint:templates` now actually validates `templates/*/template.docx` + `template.meta.json` (Node-side DOMParser polyfill via the already-present `jsdom` devDependency) — verified end-to-end against the real CPCV template and via a CLI integration test that a dangling ref fails the lint.
- M4 form + live preview + download (`src/ui`, `src/workers`, `src/core/docx/build.ts`): the full render pipeline assembling M1+M2+M3 into a single `buildDocx()` (value formatting incl. extenso/upper modifiers, cl/pt/al/ref substitution, hidden-block paragraph removal, disclaimer) that both the live preview and every download mode consume — verified as literally the same code path via tests, not just documentation. A Web Worker (`src/workers/build.worker.ts`) runs the build off the main thread; it needed an `@xmldom/xmldom` polyfill for `DOMParser`/`XMLSerializer`, which browsers' Worker scope turns out not to provide despite the spec allowing it (see ADR-0002's amendment — this was caught by testing in an actual browser, not assumed). Preview/draft-only shading (empty fields yellow, filled soft, active field stronger) is applied via real OOXML `w:shd` on a preview-only build variant — the final download stays unshaded, and "same text, different formatting" is what keeps the single-source-of-truth guarantee intact. Form generated from the template's fields + `template.meta.json` (grouped, inline validation errors); live preview via `docx-preview` (ADR-0003) with double-buffered swap; final download (blocked while any validation error remains, with a review-screen confirmation) and draft download (always available, empty fields highlighted, RASCUNHO note) both produce real `.docx` files. 9 Playwright e2e specs pass against a real Chrome browser (`channel: 'chrome'`, confirmed available in this environment) incl. axe with zero serious/critical violations and a logged (not asserted against SPEC's un-adjusted number, since it includes a deliberate debounce — see the test's own note) edit→preview latency baseline. 132 unit tests total.
- M5 templates (`templates/arrendamento`, `templates/empreitada`, `templates/procuracao`): three original, synthetic contract templates (residential lease, construction works contract, power of attorney), each with a full field/group/rule `template.meta.json` and a "PONTOS A VALIDAR POR JURISTA" section flagging what a human lawyer should confirm (none of these are legal advice). `docs/templates.md` documents the authoring workflow. `scripts/build-template-docx.ts` builds a plainly-styled `.docx` directly from a `source.txt` draft using `fflate` — kept inside the npm toolchain rather than depending on the `python-docx`-based script used to author the original CPCV template, which isn't a committed/reproducible dependency of this repo. The app's template picker (`src/ui/templateManifest.ts`, a new `empty` state in `App.tsx`) now lets the user choose among all 4 templates, fulfilling ROADMAP M5's "≥3 templates selectable" (not just present on disk). Caught and fixed a real production-only bug in the process: Vite inlines assets under 4KB as base64 `data:` URIs by default, which the app's own CSP (`connect-src 'self'`) then silently blocks `fetch()` from — two of the three new (small) templates failed to load in the production build though the dev server and all prior tests were green. Fixed via `build.assetsInlineLimit: 0`; caught by testing the actual production build in a real browser, not just `npm run dev`. 15 new unit tests (golden-output + full validation per template) plus e2e updated for the picker flow.
- M6 LLM-assisted extraction, partial (T6.1-T6.3; T6.4 eval harness deferred): `src/llm` — `LlmProvider` interface, `AnthropicProvider` (BYOK, direct browser call, temperature 0, timeout, 1 retry — CORS against the live API is HUMAN-verify, untested without a key), `ReplayProvider` (sha256-of-canonical-request-keyed fixtures, for the deferred eval harness), Zod schema + grounding (quote-must-be-substring, digit-subset check for typed fields — rejects fabrications before they're ever shown), versioned prompt (`extract.v1.md`, bundled via `?raw`, with explicit prompt-injection resistance instructions). `src/ui/ExtractPanel.tsx`: optional, collapsed-by-default panel wired additively into the existing form (reuses the same field-change handler, touches no other UI logic) — paste text, propose values, review with the matching quote shown, accept per field only (never auto-applied, warns before overwriting an already-filled field). CSP `connect-src` extended to the Anthropic API origin (ADR-0004). 17 new unit tests; existing 148 unchanged and still green.
- M7 polish (partial): Playwright config switched to its own bundled Chromium instead of the system Chrome channel, so e2e runs on CI runners (new `e2e` job in `ci.yml`, with a Playwright-report-on-failure upload); coverage now also generates `json-summary` and uploads as a CI artifact (a persistent numeric coverage badge needs a third-party service or repo-write-back automation — deferred to HUMAN, same as the CODEOWNERS placeholder). Added the missing `ADR-0006` (computed numbering) — all 7 ADRs from AGENTS.md's seed list now exist; amended ADR-0005 to record the M6 `connect-src` change. README overhauled: feature list, mermaid architecture diagram, CI/Scorecard/License badges (owner placeholder, resolve once pushed), GIF placeholder for HUMAN to record.
